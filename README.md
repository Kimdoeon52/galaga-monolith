# 편대 슈팅 모놀리식

MVC 과정 2주차 실습. 구조 없는 파일 하나로 게임을 만들고, 기능이 늘 때 수정이 얼마나 흩어지는지 숫자로 남긴다.

> **의도적 안티패턴이다.** 고정 타임스텝, 파일 분리, 헤드리스 테스트를 일부러 쓰지 않는다. 이 숫자가 4주차 MVC 버전과 비교할 기준선이 된다.

## 실행

| 할 일 | 명령 |
|---|---|
| 게임 | `run.bat` 또는 task `Love2D: Run game` |
| 문법 확인 | task `Lua: Syntax check` |
| 줄 수 표 | task `Metrics: Line and hunk table` 또는 Git Bash에서 `sh tools/metrics.sh` |

조작: `←`/`→` 이동, `Space` 발사, `R` 재시작, `Esc` 종료.

## 커밋 단위

커밋 하나가 구현 단계 하나다. `T1`, `T2` 태그는 고정 프롬프트 측정 지점이다.

1. 플레이어 이동 + 화면 경계
2. Space 발사 + 쿨다운
3. 적 편대 좌우 이동 + 끝에서 하강
4. 적 랜덤 발사 (`T1`)
5. 충돌, 점수, 라이프
6. 파티클, flash, shake
7. HUD, 게임오버, 재시작
8. 기능 추가: 보스 탄막 (`T2`)

고통 기록은 `monolith_pain.md`에 쓴다.
